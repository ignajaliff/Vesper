# Git Rules — Next.js

Convenciones de Git para un historial limpio.

## Ramas

```
main              → producción (solo código estable y testeado)
dev               → desarrollo activo, base para features
feature/[nombre]  → nueva feature o módulo
fix/[nombre]      → corrección de bug
hotfix/[nombre]   → corrección urgente directo a main
```

Ejemplos:
```
feature/catalogo-productos
feature/checkout-mercadopago
fix/calculo-total-orden
hotfix/webhook-roto
```

Regla: nunca trabajar directo en `main`. Siempre desde `dev` o una rama `feature/`.

## Commits

Formato obligatorio: **Conventional Commits**.

```
tipo(scope): descripción breve en español
```

Tipos:
* `feat` — nueva funcionalidad
* `fix` — corrección de bug
* `chore` — mantenimiento (deps, config)
* `refactor` — cambio sin cambiar comportamiento
* `style` — formato, CSS
* `docs` — documentación
* `db` — cambios en schema o policies de Supabase
* `perf` — mejoras de performance (relevante en ecommerce)

Ejemplos:
```
feat(catalogo): agregar listado de productos con ISR
fix(checkout): corregir recálculo de total en el server
db(ordenes): agregar tabla items_orden con RLS
feat(pagos): validar firma del webhook de mercado pago
perf(catalogo): pre-render de detalle con generateStaticParams
chore: actualizar a next 16.2
```

Reglas:
* Descripción en minúscula y en español.
* Sin punto final.
* Máximo 72 caracteres en la primera línea.
* Más contexto → cuerpo separado por línea en blanco.

## Cuándo hacer commit

* Al terminar una feature o módulo funcional.
* Al corregir un bug.
* Antes de un cambio grande (checkpoint).
* Nunca commitear código roto o con errores de TypeScript.

## .gitignore obligatorio (Next)

```
node_modules/
.next/
out/
build/
.env
.env*.local
*.log
.DS_Store
.vercel
next-env.d.ts
```

`.env.example` SÍ se commitea (sin valores reales).

> Atención: `.next/` y `.env*.local` son específicos de Next. Verificar que `.next/` nunca entre al repo.

## Flujo de trabajo con IA

Cuando la IA hace cambios:
1. Revisar el diff antes de commitear.
2. Verificar que no se commitearon secretos (`.env`, access tokens de Mercado Pago, service key).
3. Verificar que `npx tsc --noEmit` pasa.
4. Verificar que el build pasa antes de pushear a main.
